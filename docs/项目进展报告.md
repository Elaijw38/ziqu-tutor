## 一、摘要

本项目面向郑州大学汉字类通识课，做一个**能查、能练、能评**的课程助教：学生问字形或字义，助教只依据课程材料作答并给出可核对的出处；教师和学生能看到按知识点组织的学情；系统能按薄弱点出题、判分，并把结果写回学习记录，形成「问 → 诊 → 练 → 评」闭环。

截至本报告，系统已实现并在本地稳定运行，核心能力均有**可复现的验证**：

| 关键指标 | 数值 | 验证方式 |
|---|---|---|
| 课程知识库 | 1391 条材料，覆盖 1179 个字 | `/api/health` |
| 甲骨字形库 | 1168 个现代字可渲染甲骨字形 | `/api/glyph/<字>` |
| 课程字表 | 146 字（王邑 61 + 讨伐 21 + 名录 88 去重） | `/api/health` |
| 固定评测集 | **45 条，通过 45 条（100%）** | `tests/run_eval.py` |
| 智能体工具 | 4 个：检索 / 学情 / 出题 / 判分 | 实测三轮自主链路 |
| 库外问题拒答 | 8/8 正确拒答 | 评测集 o01–o08 |
| 错误前提纠正 | 6/6 正确纠正 | 评测集 f01–f06 |

## 二、问题与定位

课程教学中有三个具体困难：

1. 学生课后问“这个字为什么这么写”，教师无法逐一答复；
2. 教师难以知道每个学生到底卡在哪个构件、哪个知识点；
3. 练习与评讲依赖人工，难以按个体薄弱点即时生成。

对应的产品假设（待教师与学生验证，不作已证结论）：

- 初学者难以把“字形观察”“构件分析”“释读解释”三者联系起来；
- 课程材料中的字例与出处分散，学生不便即时核对；
- 通用问答容易给出听起来合理、却没有课程依据的解释。

系统的设计取向因此是：**宁可少答，不可无据**。

## 三、系统架构

```
前端（web/index.html）
  问答三态 / 学情诊断 / 随堂练习 · 郑大 UI
        │
        ▼
服务端（src/server.py，Python 标准库）
  /api/ask /api/diagnose /api/quiz /api/grade /api/glyph/<字> /api/health
        │
        ├── ask.py        问答编排：Dify → 大模型 agent → 本地抽取 → 拒答（逐级降级）
        ├── llm.py        OpenAI 兼容客户端 + 4 个工具的 function-calling 循环
        ├── glyphs.py     甲骨字形渲染（解析上游 stroke 字段 → SVG）
        ├── retrieval.py  中文检索（字 1-gram + 2-gram + TF-IDF，零依赖、可解释）
        ├── quiz.py       组卷（题型轮转、错题优先、可按知识点）与判分
        └── learning.py   四库联动诊断（知识点 / 题目评分 / 学习证据 / 诊断干预）
        │
        ▼
数据层
  data/kb.jsonl        1391 条材料（每条带出处）
  data/upstream/       甲骨字形数据集 1203 条（CC BY 4.0）
  data/curriculum.json 课程知识点库
  data/diagnosis.json  诊断与干预库（阈值/状态文案/错因规则全部可配）
  data/learners.db     学习证据库（SQLite，按访客隔离）
```

**设计原则**：零第三方 Python 依赖、可离线运行、可解释、可降级。

## 四、已实现的能力

### 4.1 带出处的问答（三种作答模式）

| 模式 | 行为 |
|---|---|
| 直接解释 | 完整解释 + 出处材料卡（标题 + 依据原文 + 来源） |
| 给我提示 | 只给第一条线索并反问，点「看答案」才展开 |
| 考考我 | 只给甲骨字形（**不显示现代字**），四选一，作答前隐藏出处 |

答案只来自知识库；资料不足时使用固定拒答句式；引用不匹配等问题已在评测中覆盖。

### 4.2 甲骨字形

解析上游数据集 `stroke` 字段（首值为点数，随后成对坐标，`(-64,0)` 分笔、`(-64,-64)` 收尾）渲染为 SVG：
`GET /api/glyph/<字>?size=512&download=1`，覆盖 1168 个现代字。回答下方自动展示 3–4 张字形卡。

与字趣中已校准字形做过对照（木、田、月等形状一致），确认解码正确。

### 4.3 学情诊断（按知识点，不按区域）

- 每个知识点显示“作答数 / 正确数 / 状态 / 证据量”；
- 状态分「证据不足 / 建议巩固 / 初步掌握」等，**阈值与文案在 `diagnosis.json` 里配置**，代码不写死；
- 错因映射到具体题目与可观察行为（如“把笔画数和现代通行笔画混用”），**不输出人格标签**；
- 样本不足时明确显示“证据不足 / 仅供本次练习参考”。

### 4.4 组卷、判分与回写

- 题型：构件分析 / 字义理解 / 字形笔画，按知识点与错题优先组卷；
- 判分写入 SQLite 证据库，学情页随之变化；
- 交卷后逐题给错因讲解与一条优先改进建议。

### 4.5 智能体工具编排（本次重点）

四个工具，全部由模型自主决定调用，并有严格的“不许自己来做”的规则：

| 工具 | 做什么 | 约束 |
|---|---|---|
| `search_kb` | 检索课程材料 | 回答事实前必须先调 |
| `get_learner_state` | 读程序算好的诊断 | 统计数字不得改写 |
| `generate_quiz` | 按学情出题（可指定知识点） | **禁止模型自己编题** |
| `submit_answers` | 判分并写回证据库 | **禁止模型自己算分** |

**实测三轮自主链路**（同一会话）：

```
学生：给我出三道题
  → 模型自主调用 generate_quiz → 出 3 题，答案留服务端

学生：三题都选 A
  → 模型识别为作答，调用 submit_answers → 67 分，逐题讲错因，写回证据库

学生：针对笔画再出一组
  → 模型自主调用 generate_quiz(kp=笔画) → 只出笔画题
```

### 4.6 可信度工程

| 机制 | 说明 |
|---|---|
| 前置核对（代码级） | 识别“X 由 A 和 B 组成”类断言，与知识库比对，不符则先纠正，不交给模型自由发挥 |
| 答案留服务端 | 出题时选项与答案只在服务端，模型看不到答案，泄露面更小 |
| 出处材料卡 | 每条出处带标题与依据原文，可展开核对 |
| 降级链 | Dify → 直连大模型 → 本地抽取式，任一层失败不白屏 |

## 五、效果验证

### 5.1 固定评测集

`tests/eval_set.jsonl` 共 45 条，六类，评分规则写在数据里（`must_all / must_any / must_not / citation / cite_title_any / refuse`）：

| 类别 | 题数 | 结果 |
|---|---|---|
| 直接回答 | 12 | 12/12 |
| 形近字 | 8 | 8/8 |
| 争议与限制 | 5 | 5/5 |
| 库外问题 | 8 | 8/8 |
| 错误前提 | 6 | 6/6 |
| 出处核对 | 6 | 6/6 |
| **合计** | **45** | **45/45（100%）** |

### 5.2 评测发现并修复的真实缺陷

首轮 44/45，失败项为：

> 问：木由宀和豕组成，对吗 → 答：**对**，你说的就是「家」字。

模型顺着错误前提作答。修复方式不是改提示词，而是**代码级前置核对**：

```
识别「X 由 A 和 B 组成」→ 查知识库中 X 的真实构件
  · 不一致 → 明确“不是”，给出正确构成，并指出该构成属于哪个字
  · 目标字无构件（独体字）但 A+B 属于别字 → 同样纠正
  · 完全一致 → 放行给模型细说
```

修复后重跑：45/45，且未影响其他类别。

### 5.3 验证的局限（如实说明）

- 评测集由项目组自拟，**具有“按答案出题”的风险**，只能证明“无明显退化”，不能证明“教学效果”；
- 覆盖面仅 146 个课程字，课程外问题只能拒答；
- 尚无真实学生与教师参与。

## 七、差距与风险

| 项 | 现状 | 影响 |
|---|---|---|
| 模型 | 第三方 API（DeepSeek） | 不扣分（评审不以模型规模为准），但需诚实说明 |
| 部署 | 仅本机运行 | 无法对外服务 |
| 多用户 | SQLite 按访客隔离，无班级 | 教师无法看班级 |
| 教师端 | 无 | 备课流程不便 |
| 讲义出题 | **未实现** | 教师临时给的讲义无法出题（设计已完成，见下） |
| 语料深度 | 缺卜辞例句、分期、异体对照 | 领域深度受限 |
| 工具依赖 | 依赖 function calling | 换校内本地模型需先验证 tools 支持 |

### 教师讲义出题的实现要点（已设计）

```
教师粘贴讲义 → 切段并抽候选考点 → 与字形库/知识库对齐
  → 模板化出题（笔画题取数据集标注；构件题取知识库 comps；
     字义题取讲义原句 + 释义；理解题挖空原句）
  → 教师审核（勾选 / 改选项 / 删题）
  → 学生练习 → 判分写回证据库（归到本课知识点）
```

限制（需向教师说明）：讲义中超出字形库的新字，只能出“讲义理解题”，不出字形题；开放题只给参考反馈，不给精确分数。

## 十、结论

系统已达到“**可演示、可验证、可解释**”的原型水平：

- 能自主完成“查资料 → 看学情 → 出题 → 判分 → 按弱点再出题”的多步任务；
- 关键能力有固定评测集支撑，缺陷能被评测发现并修复；
- 边界与限制已如实写入报告，不作为卖点夸大。

它当前的短板不在模型，而在**语料深度、教师端流程与真实课堂验证**——这也正是下一阶段的工作重心。
