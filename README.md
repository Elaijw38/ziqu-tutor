# 甲骨文 AI 助教 · 郑州大学（ziqu-tutor）

面向「郑州大学首届 AI 智能体创新应用大赛」A2 任务（AI 助教 · 教、学、评闭环）的智能体原型。
**独立项目**：不修改字趣本体，只从它那里**只读**导出知识库。

**助教形象：龟宝**——沿用本人另一件作品「字趣」的原创小向导形象（只读复用，原作品未改动），
作为助教人格与头像；对话里自称「我」，语气亲切但不卖萌。

**界面按郑大校园应用来做**：顶栏「郑州大学 + 赛事标识」，场景条标明文学院 / 通识课 / 班级（示例，可配置），配色用校徽的红色元素（郑大红 #a4231f）配藏青，正文用宣纸骨白，兼顾郑大身份与甲骨题材。

## 现在能干什么

- **带出处的问答**：问字形、读音、笔画、字义与构形，也可以问甲骨文的历史、材料、占卜、断代与六书；
  每条回答都附原文条目，可展开核对。
- **不编造**：答案只来自本地知识库（1,391 条 / 覆盖 1,179 个字），每条都带 `source`；
  问不到就明说没有，或反问“你问哪个字”。
- **知识来源彼此独立**，不依附某一款教学游戏：

| 层 | 规模 | 来源 |
|---|---|---|
| 字形库 | 1,203 个甲骨字形 / 1,168 个现代字 | Oracle Bone Glyphs 数据集 v0.3，CC BY 4.0，DOI 10.5281/zenodo.22467946 |
| 甲骨文通识 | 24 条 | 王宇信《甲骨学通论》、裘锡圭《文字学概要》、董作宾《甲骨文断代研究例》、《说文解字·叙》等 |
| 字源解读 | 29 条 | 《说文解字》 + 裘锡圭《文字学概要》 |
| 课程案例（可选） | 170 条 / 146 字 | 字趣《殷商王邑》《构件讨伐》，只读导出 |

- **两套口径分开**：`1,179 字` 是“能查多少字”的能力边界；`146 字` 是课程字表，
  学情覆盖率只按后者计算——否则字库一扩，覆盖率就从 20% 掉到 2%，诊断会失真。

## 怎么跑

```bash
python src/build_kb.py     # 上游字表 + 通识/字源 + 课程案例（只读）→ data/kb.jsonl
python _enrich_kb.py       # 可选：给课程条目补会意解释
python _merge_kb.py        # 可选：合并成 Dify 单文件知识库
python src/server.py 8770  # 启动服务
# 浏览器打开 http://127.0.0.1:8770
```

自检：

```bash
curl http://127.0.0.1:8770/api/health
# {"ok": true, "kb_rows": 1391, "chars": 1179, "course_chars": 146, "llm": false, ...}
```

**零依赖**：只用 Python 标准库，不需要装任何包、不需要联网（上游数据已随仓库提供）。

## 已实现的三条"不翻车"设计

1. **不知道就说不知道**：相关度不足、或问句里的字不在知识库时直接拒答，不拿别的条目凑。
2. **同一字只说一次**：名录与关卡条目常指向同一个字，去重后取信息量最大的一条；
   问"怎么打"优先给带打法的条目，问"怎么写"优先给带构形的条目。
3. **出处是真的**：字形数据 CC BY 4.0（DOI 10.5281/zenodo.22467946），
   王邑实物点标注"教学示意图（非考古复原）"，不冒充考古结论。

## 接大模型

不接模型也能用（抽取式回答）。要接，复制 `config.example.env` 为 `config.local.env`，填三行：

```
ZQ_LLM_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
ZQ_LLM_KEY=sk-你的key
ZQ_LLM_MODEL=qwen-plus
```

重启服务后看是否生效：

```
curl http://127.0.0.1:8770/api/health
# {"ok":true,...,"llm":true,"model":"qwen-plus"}
```

**为什么用 OpenAI 兼容协议**：百炼、火山方舟、DeepSeek、智谱、本地 Ollama/vLLM 都提供
`/chat/completions`，换平台只改三个环境变量，代码不动。

**接入后的行为（真正的 agent）**：

1. 模型自己决定调哪个工具，四个工具对应四类诉求：

   | 工具 | 什么时候调 | 返回 |
   |---|---|---|
   | `search_kb` | 问字形、字义、构件、打法 | 知识库原文 + 署名出处 |
   | `get_learner_state` | 问「我哪里弱」「接下来学什么」 | 课程字覆盖、作答正确率、按题型的正确率、高频错字、错题构件 |
   | `generate_quiz` | 说「出两道题」「考考我」 | 题目与选项（**不含答案**） |
   | `submit_answers` | 学生报出选项 | 得分、逐题错因，并写回学情 |

2. 服务执行工具，把结果以 JSON 回填给模型；最多 4 轮，轮次用尽会再要一次纯文本回答（不静默降级）
3. 模型基于这些事实作答（系统提示词禁止补充事实之外内容）
4. 检索命中的条目、出处、以及**调了哪些工具**（接口 `trace` 字段）一并返回，前端显示成
   「查知识库 · 5 条」「出题 · 2 道」这样的徽标，答辩时可以直接指着看

**多轮**：前端带最近 3 轮上文（`history`），所以「日为什么写成圆的」之后问「那它怎么打」，
「它」能正确指回「日」。Dify 链路另有 `conversation_id`。

**答案与题目分开存**：`generate_quiz` 只把题目交给模型，答案留在服务端，模型没机会漏答案；
评阅必须走 `submit_answers`，由服务端算分并写学情，避免模型“自己判自己”。

**三态口径**：`answer`（答了）/ `refuse`（知识库确实没有）/ `clarify`（没听清，反问）。
后两种一律不挂出处——否则会出现“答了却没有依据”的观感。

**降级**：未配置、超时（默认 25s）、额度用尽、返回异常 —— 一律退回本地抽取式回答，
接口不报错、页面不白屏。现场演示这点很关键。

**密钥安全**：key 只在服务端读取，前端拿不到；`config.local.env` 已加入 `.gitignore`。

**验证**：`python tests/test_agent.py` 用假模型跑通「工具调用 → 检索 → 出处合并 → 多轮 → 三态 → 出题」，
不需要真 key；真实链路的出题→评阅闭环已实测（50 分、逐题错因写回学情）。

## 可选：接入大模型

不配置也能跑（抽取式回答）。要更自然的措辞，设三个环境变量即可：

```
ZQ_LLM_KEY / ZQ_LLM_BASE / ZQ_LLM_MODEL
```

系统提示词里已写死"只允许使用给定事实作答，不得补充事实之外的知识"，
所以接入大模型后仍然是**可溯源**的，不会变成自由发挥。

## 部署到公网（把链接发给别人）

三种方式，按“多久能拿到链接”排序：

| 方式 | 命令 | 适用 | 代价 |
|---|---|---|---|
| 临时隧道 | 下载 `cloudflared` 后 `cloudflared tunnel --url http://127.0.0.1:8770` | 今天就要发给评委/同学看 | 链接随进程变，本机必须开机 |
| 云服务器 | 传代码 → `ZQ_HOST=0.0.0.0 PORT=80 python3 src/server.py` | 正式演示、稳定 | 要一台服务器 + 安全组放行端口 |
| 容器平台 | `docker build -t ziqu-tutor .` 后推镜像 | 长期维护、可回滚 | 要镜像仓库/平台账号 |

**对外必须配的三个环境变量**（不配则保持“只有本机能访问”的默认行为）：

```
ZQ_HOST=0.0.0.0          # 对外开放
ZQ_ACCESS_CODE=zzu2026   # 邀请码门禁：页面与接口都要凭码
ZQ_RATE_PER_HOUR=60      # 单 IP 每小时提问上限，防刷模型额度
```

`PORT` 由平台注入（Render/Fly/容器都会给），代码已兼容。

**安全清单（发之前逐条确认）**

1. `config.local.env` **不进镜像、不进压缩包**（`.dockerignore` 与 `.gitignore` 都已排除）；
2. 模型 key 只通过平台的环境变量注入，不写进任何文件；
3. 邀请码务必设置，否则任何人拿到链接都能消耗你的模型额度；
4. 仓库若推送到 GitHub/Gitee，**先确认 git 历史里没有明文 key**（此前已核查并清理，旧 key 也已作废）；
5. 公开部署建议套一层 HTTPS（平台一般自带；自建服务器用 Caddy/Nginx 反代）。

**学情按人分开**：学情存在 `data/learners.db`（SQLite，标准库），每个浏览器拿一个随机
`zq_vid`（HttpOnly cookie，不含任何个人信息），各存各的记录；A 交的卷不会记到 B 头上。
- 换设备、清浏览器数据、开无痕窗口 → 拿到新的 vid，等于从头开始；
- 页面上有「清空我的记录」与「载入示例学情」（课堂演示用，会明确标注"含示例数据"）；
- `data/learner.json` 是旧版单文件，只在建库时导入成示例桶，之后不再写入；
- 没有 cookie 的调用（curl、脚本）落到共享的 `local` 桶，学情不能当个人证据用。

**四库联动（逻辑数据集，一个 SQLite + 两份 JSON，不建四套库）**

| 库 | 存放 | 主键 | 关联 |
|---|---|---|---|
| 课程知识点库 | `data/curriculum.json` | `knowledge_point_id` | 能力维度 `dimension_id`；题型 → 知识点 `type_to_kp` |
| 题目与评分库 | `learners.db` 的 `quiz_items` 表 | `item_id` | `quiz_id`、`knowledge_point_id`、标准答案、难度、出处 |
| 学习证据库 | `learners.db` 的 `attempts` 表 | `attempt_id` | `vid`（匿名）、`item_id`、`knowledge_point_id`、正误、时间 |
| 诊断与干预库 | `data/diagnosis.json` | `cause_id` | 匹配规则（题型/正误/差值）、提示、讲解、补练动作 |

- 评阅以服务端 `quiz_items` 的答案为准，客户端回传的 `answer_index` 不参与判分；
- 旧数据（`learner.json` 里的 attempts，没有题目与选项）在首次诊断时迁进 `attempts` 表，
  补 `kp_id`（按题型映射）、`item_id` 记 `legacy.*`；这类记录只能按题型归因，错因统一标
  「暂无法归因」，不硬编；
- 阈值和状态文案全在 `data/diagnosis.json`：`min_evidence=3`、`solid_evidence=5`、
  `mastery_acc=80`、`weak_acc=60`，改配置即可调整，页面不写死；
- 大模型只拿聚合摘要（知识点状态、错因计数、错字），不拿逐题作答明细，也不许改数字。

## 两种大模型接法

| 接法 | 配置 | 适用 |
|---|---|---|
| 直连模型（OpenAI 兼容） | ZQ_LLM_BASE/KEY/MODEL | 想自己控编排、成本低 |
| **Dify 应用** | ZQ_DIFY_BASE/KEY | 知识库与流程在 Dify 里做，回答自带检索来源 |

优先级：**Dify → 直连模型 → 本地抽取式**，任一层失败自动降级。

Dify 走的是原生 /chat-messages，因为只有它会返回 metadata.retriever_resources；
兼容端点只有纯文本，会把可溯源丢掉。

每个命中分段会被拆成三部分，前端据此还原「出处」折叠条：

| 字段 | 取自 | 例 |
|---|---|---|
| `title` | 分段首行（`##` 标题） | 构件讨伐 · 家（一阶 · 合体字） |
| `source` | 分段末尾的 `出处：` 行 | 字趣《构件讨伐》一阶 · 合体字 · CC BY 4.0, DOI 10.5281/zenodo.22467946 |
| `snippet` | 正文首 150 字 | 「家」属于一阶 · 合体字，字形构成：构件 宀+豕。 |

**别拿 `document_name` 当出处**——那只是上传的文件名（`dify-kb-merged.md`），对学生没有任何核对价值。
同一分段被重复召回时只保留一条；Dify 的拒答同样是 200 + 固定句，服务端会认出来并把
`refused` 置为 true、不挂无关出处。

另外两处工程处理：
- **本地地址绕过系统代理**（否则 127.0.0.1 会被 http_proxy 拦成 502）；
- **回答清洗**：去掉模型自带的结尾 //、答： 前缀等杂质。

测试：python tests/test_dify.py（假 Dify 独立进程，不需要真 key）。
